# 修复商店遗物漏入库、OCR 换行重复计数，增加存档库存配套备份

## 比较基线

本报告仅描述相对于上次 PR 提交 `356ec2e` 的新增变化，不重复列举首次 PR 已包含的评分、库存管理及配装优化功能。基线对应本地记录的 `origin/feat/relic-management-scoring-clean`；整理时远程查询因网络错误未完成，未验证远端是否另有更新。

## 功能变化

### 商店保留遗物自动入库

此前商店提示保留后，只保存筛选历史，没有写入遗物库存。现在复用库存记录器，将合格且识别可信的遗物保存到库存，包含颜色、词条、评分明细、有效词条数、匹配预设与操作状态。

颜色识别使用与 OCR 相同的一帧完整截图和已有颜色模型，按商店布局裁剪；颜色不确定时保存为未知。每轮购买使用独立扫描编号，两件词条完全相同的新购遗物分别记录。无法确认的识别结果不标为确定拥有。写入异常会在日志中提示，不改变游戏中的保留操作。

### 修复 OCR 换行处理

送葬者“使用祷告将辅助效果附加在自己身上时提升物理攻击力”换行后，首行曾被模糊纠错补全，下一行“提升物理攻击力”又单独计为有效词条。现在当首行是匹配词条的不完整前缀，且与下一行拼接能准确还原同一词条时，合并两行。

同时修复两项相关问题：合并必须通过纠错阈值；被合并的续行只跳过一次，避免连带丢失下一条真实词条。完整独立词条及其后真实存在的物理加攻仍分别保留。

### 存档与遗物库存配套备份

新备份在游戏存档旁保存同名 `.relic_inventory.sqlite3` 文件，使用 SQLite 备份接口生成数据库快照。还原前校验配套数据库；还原时保留现有文件的 `.bak`，库存替换失败时尝试回退游戏存档。重命名、删除备份同时处理配套库存。

旧的仅存档备份继续可用，还原它们时保留当前库存。备份列表显示“含遗物库存”或“仅存档”，还原确认框说明覆盖范围；配套还原成功后刷新遗物管理和配装优化页面。

## 验证与限制

- OCR 回归：换行专属词条仅计一次，下一条真实词条仍保留，独立物理加攻不被吞掉，低于纠错阈值的合并不被视为成功。
- 商店回归：调用商店布局颜色识别；分别提交同词条的两件实物记录；无法确认的结果不标为确定拥有。该测试模拟库存写入接口，不替代游戏内端到端验证。
- 存档回归：配套及重复还原、旧备份兼容、损坏数据库拒绝还原、配套重命名删除。
- 以上共 7 项针对性测试已通过；修复版 EXE 已成功构建。未在测试中操作真实游戏存档。
- 历史漏记遗物不凭不完整历史自动补入，需通过 F9 仓库检索补齐。旧记录中的错误 OCR 内容也不自动猜测修正。
- 两个独立文件的更新并非跨文件原子事务；异常回退不能等同于对断电或进程被强制终止的完整事务保证。
