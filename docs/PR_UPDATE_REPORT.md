# 以存档同步统一遗物库存，修复 OCR 并精简颜色识别依赖

## 对比范围

本报告描述相对于上一轮功能 PR 提交 `356ec2e` 的补充改动。当前分支继承补充提交 `ada7c36`，保留 OCR 修复，以直接读取存档统一库存来源，移除商店、仓库自动入库和存档、数据库配套备份。

## 功能变化

### 库存统一从存档同步

商店筛选与仓库清理不再向遗物库存数据库写入记录。筛选、出售、收藏以及评分日志仍保留，但不再逐件识别颜色。库存通过“刷新库存”从存档读取，保留用户手动编辑入口，避免截图识别与存档同步同时维护库存造成重复或不一致。

### 修复 OCR 换行处理

修复送葬者“使用祷告将辅助效果附加在自己身上时提升物理攻击力”被拆分后，同时匹配完整词条和“提升物理攻击力”，导致重复计分的问题。修正两个纠错入口的断行合并、匹配阈值检查及重复跳过行为。

### 从游戏存档同步遗物库存

- 遗物管理的“刷新库存”改为选择游戏存档及角色槽位，确认后同步该槽位的实际库存。
- 复用 PR #9 的只读存档解密与解析实现，保留其许可文件；不修改游戏存档，不启用遗物合法性判定功能。
- 通过词条 ID 映射到程序现有词条库。普通官方遗物的词条可匹配深夜词条库；官方专用效果使用已校对的官方遗物目录名称。
- 同步普通、深夜遗物的颜色及全部已识别词条，官方遗物仅按实际持有情况录入，不再默认玩家拥有全部官方遗物。
- 新增 `save_items` 表记录存档来源、槽位及物品标识，重复同步复用记录；两件词条相同的实物仍分别保留。
- 确认同步后，以所选槽位替换当前可用库存，旧扫描记录保留但不再作为已拥有库存参与配装。
- 存档读取期间发生变化、词条无法完整映射或写入失败时，不覆盖现有库存；数据库更新在事务中完成。

### 移除旧库存检索及配套备份

- 删除仓库检索按钮、F9 快捷键及对应执行分支，以存档同步替代。
- 取消存档与遗物数据库的绑定备份、联动还原、重命名和删除，以及界面标识、恢复刷新信号和旧测试。
- 存档备份、恢复只处理游戏存档。恢复后需要通过“刷新库存”更新遗物库存。
- 历史配套数据库备份文件不再使用，但不主动删除用户已有备份。
- 存档写入先复制到临时文件再替换，恢复前保留原存档 `.bak`。

### 导航图标

遗物管理保留方格图标，配装优化使用机器人图标，避免两个入口使用相同图标。复用现有 UI 图标库。

## 依赖与发布包清理

- 移除未使用的遗物合法性判定代码及 `AttachEffectTableParam.csv` 概率表，减少约 0.55 MiB 参考数据。
- 删除 `core/relic_color.py`、`data/relic_color_model.joblib` 和相应打包条目，移除 `scikit-learn`、`joblib` 安装依赖，并排除它们及 `threadpoolctl` 的打包收集。库存颜色直接从存档读取。
- 删除旧图像库存写入接口及扫描去重分支，保留历史表，避免破坏已有数据库兼容性。
- OCR、OpenCV 仍用于商店和仓库自动化；SciPy 仍用于配装求解，继续保留。
- 不包含个人库存、存档、预设配置、日志、截图、EXE、构建目录或虚拟环境。

- 本地完整程序（仅 EXE 与运行库，不含用户数据）实测由 408.89 MiB 降至 386.35 MiB，减少 22.54 MiB。新包中未包含颜色模型、sklearn、joblib 或 threadpoolctl。

## 验证与限制

- OCR 修复沿用此前游戏实测结果；商店自动入库已移除。
- 当前存档解析以现有真实备份进行只读验证：读取 1,225 件遗物，其中 37 件对应官方遗物目录，未出现未映射词条。精简解析模块后结果一致。
- 删除颜色识别和自动入库后的 4 项针对性检查通过（OCR 换行、匹配结果及逐件日志不依赖库存数据库）。
- 库存重复同步、不同实物保留、异常事务回滚、官方遗物非默认持有及相关界面检查通过。
- 存档备份还原的独立回归检查通过：无需遗物数据库即可备份，旧配套数据库不影响恢复，复制失败不覆盖当前存档。
- 尚未声明新版全部流程已在实际游戏中验证。解析依赖当前 PC 存档结构及参考数据，后续游戏更新可能需要适配。
- 每次同步只使用一个选定角色槽位，且反映所选文件的保存时点；不会自动合并不同槽位，也不会监控游戏存档变化。
