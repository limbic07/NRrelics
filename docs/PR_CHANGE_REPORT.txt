PR 标题：增加遗物综合评分、库存管理与配装优化

对比范围
以 GitHub 原版提交 a318132 为基线，描述最终版本相对于原版的整体变化。下载的 NRrelics-master.zip 中的 Python、打包配置、TXT 和 Markdown 文件已与该基线核对一致。

功能变化

1. 综合评分与分级预设
原有筛选主要根据有效词条数量和黑名单判断。新增可选综合评分，在双有效／三有效门槛之外，同时检查保留线和备选线；达到备选线的遗物也会保留。
正面词条分为重要、次要、锦上添花，深夜负面分为不可接受、很伤、几乎无负面，各等级分数和阈值可配置。专用预设继承通用预设，允许覆盖等级、排除继承词条，以及将特定负面按正面效果计分。
关闭评分时沿用原有数量筛选。导入导出支持等级和评分配置，兼容缺少评分字段的旧预设。

2. 内置流派与官方遗物
增加分角色的普通／深夜流派预设，无需额外导入 JSON。新建专用预设先选择角色，自动生成“角色｜流派名称”，用于配装页面归类。
内置 118 件官方遗物的名称、颜色和固定词条，并默认加入可用库存。官方信息不可修改或删除；普通预设可指定每件官方遗物的整体分数，未指定时按有效词条计分。评分窗口可展开查看固定词条。
商店和仓库页面提供“恢复默认预设”，经二次确认后替换为内置版本，不自动生成备份。

3. 仓库检索与筛选结果
增加 F9 仓库检索，复用仓库遍历和识别流程，仅录入数据，不执行收藏或售出。
仓库筛选增加逐件结果，记录词条、评分明细、总分、有效词条数、匹配预设、判定和实际操作状态，并同步到日志及仪表盘。
评分判定与操作结果分别保存，例如“淘汰”不等于“已售出”。OCR 不完整时禁止破坏性操作，操作未确认时记录待核实状态。
增加遗物图标颜色识别，支持红、蓝、绿、黄；低置信度返回未知。

4. 遗物管理
新增独立的遗物管理页面，通过 SQLite 保存本地库存、扫描记录和评分快照。
支持添加、双击编辑、批量删除非官方遗物及按词条筛选。编辑时从可搜索的词条库选择，不允许直接输入任意词条。
深夜遗物最多三组词条，每组最多一条正面和一条负面，负面必须配有正面。相同词条的不同实物保留独立记录。

5. 配装优化
新增独立的配装优化页面，分别选择普通和深夜预设，也可只优化其中一类。
按角色可用器皿、槽位颜色和库存求解最高分组合。可指定必备词条或官方遗物：同组满足任意一项，不同组必须全部满足；普通和深夜同名词条共用一个条件。
最低分比例默认为最优分的 75%。先返回前 10 套，继续请求时查找后续 10 套；同一组遗物的槽位排列不重复列出。
计分区分可叠加、同名去重及特殊叠加规则。只有求解器确认最优才返回对应排名，超时或无法证明最优时报告失败。
结果按器皿槽位从左到右展示，包含库存行号、颜色、词条、单项分数、每件贡献和组合总分。

前端变化
商店和仓库共用分级预设编辑器，通过等级按钮选择词条，可查看已选词条及等级。
可勾选列表支持右键整行切换状态；数值框和下拉选项禁止滚轮改值。
遗物表格使用固定信息列宽、悬停效果与官方遗物锁定标记，禁止直接改动表格文本。
存档管理增加打开备份目录和游戏存档目录的快捷按钮。
预设列表在页面首次显示时加载，折叠词条在首次展开时创建；单个预设创建、编辑、删除只更新对应卡片，并同步另一个页面。

后台实现与主要文件
core/relic_matcher.py、core/relic_scoring.py：扩展原有共享匹配器，提供分级评分、最高分候选和失败原因，商店与仓库共同调用。
core/preset_manager.py：维护等级、继承覆盖、官方遗物分数、内置预设和旧数据兼容。
core/repo_cleaner.py、core/relic_inventory.py、core/relic_color.py：连接仓库遍历、颜色识别、操作确认与 SQLite 持久化；数据库操作使用事务，移除库存保留扫描记录。
core/loadout_optimizer.py：使用 SciPy MILP 建模，计分和颜色约束不依赖槽位顺序，展示时再分配槽位；不同调用入口共用 K 最优求解流程。
core/official_relics.py：统一官方目录读取和识别，供库存、评分窗口和优化条件复用。
ui/pages/page_relics.py：实现库存管理、后台求解和结果展示。求解使用参数与库存快照，避免界面操作改变进行中的问题。
ui/dialogs/：实现分级预设编辑、角色选择、官方遗物评分与条件组编辑。
ui/pages/page_shop.py、page_repo.py、page_settings.py、page_save.py、ui/main_window.py、main.py：接入评分配置、导航、逐件结果、快捷入口和统一输入行为。
data/：增加流派预设、器皿、官方遗物目录与颜色模型。

依赖与构建
库存使用标准库 sqlite3，界面沿用现有 PySide6 和 Fluent Widgets。
组合优化引入 SciPy，颜色模型使用 scikit-learn 和 joblib。OpenCV 使用 headless 发行版，满足截图处理而无需其窗口界面。
打包配置显式列出运行资源和模型需要的动态导入，排除不需要的开发、绘图模块及 OpenCV 视频解码库。用户配置、库存和存档备份作为外部数据保存，不作为内置资源打包。
本地构建目录、测试临时文件和用户数据不纳入源码提交。

验证与边界
39 项相关测试通过，覆盖评分、预设编辑、库存、仓库检索、官方遗物、配装优化、分批结果、滚轮与右键、预设增量加载。最终求解接口另通过 5 项专项测试；这 5 项与前述测试存在重合，不计为 44 项独立测试。
目录 JSON 格式检查、源码差异格式检查和 Windows EXE 构建通过。
游戏内出售、收藏和存档还原尚未完成实机回归，仍需在实际游戏环境验证。
